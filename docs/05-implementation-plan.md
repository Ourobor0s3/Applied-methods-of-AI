# 3. План реализации и методология

## 3.1. Этап 1: Сбор и агрегация данных

- Разработка Python-скриптов для регулярного опроса API
- **CryptoPanic:** запрос новостей по `currencies=BTC`, `filter=important`
- **CoinMarketCap:** периодический (раз в час) запрос котировок
- Сохранение сырых JSON-ответов в PostgreSQL или S3

## 3.2. Этап 2: Обработка данных и инжиниринг признаков

### Рыночные данные
- Очистка и приведение к часовому временному ряду
- Лаговые признаки: `price_lag_1h`, `price_lag_2h`, `volume_lag_1h`
- Скользящие средние и технические индикаторы

### Новостные данные
- **Агрегация по часам**
- **Количественные признаки:**
  - Количество новостей
  - Средний `panic_score`
  - Net Sentiment = `(positive - negative) / (positive + negative + 1)`
- **Тематическая кластеризация** (LDA, KMeans на эмбеддингах)

### Объединение
Финальный датасет формируется по временной метке (часу)

## 3.3. Этап 3: Построение и обучение моделей

| Подход | Модели |
|--------|--------|
| Базовые | Линейная/логистическая регрессия, Random Forest, XGBoost, LightGBM |
| Продвинутые | LSTM, Temporal Fusion Transformer |

**Скорректированная цель:** Прогноз диапазона волатильности вместо направления цены (на основе выводов Phase 1)

## 3.4. Оценка и валидация

- Кросс-валидация на исторических данных
- Сравнение моделей с новостными признаками vs. только рыночные данные
- Метрики: RMSE (регрессия), F1-score (классификация режимов волатильности)
